# BEDS portable UI — package rules

Read [the documentation map](docs/README.md), then only the affected contract. In this repository, edit canonical `docs/design/espaco-library/`; package `docs/` is generated by the build.

Active migration: [Agnostic DS](docs/AGNOSTIC-DS.md) supersedes the legacy ban on
app-owned page composition. BEDS owns reusable components and style guidance;
apps own identity, page layout and business policy. Do not add product logos or
complete screens to the runtime. The migration ledger records unfinished work.

- This portable DS is separate from legacy Curriculol typography/palette and the old Espaço prototype. [Foundations](docs/FOUNDATIONS.md) owns approved visuals; do not mix systems.
- Two themes; one validated caller-owned provider brand color. Named semantic variants protect BEDS component internals. Apps may use their own semantic HTML, layout CSS, icons and identity assets; they may read tokens but must not override private `.es-*` selectors or redefine `--es-*` properties.
- Components own presentation and semantics; callers own copy, data, requests, routing and business rules. Use controlled state; never invent successful operations.
- Keep app-specific patterns and complete pages in the app. A new reusable component requires a single job, two unrelated uses, BEUI sourcing, a shared contract/API, catalog example, states and focused light/dark responsive evidence. App layout styling is expected, not a workaround.
- Before building or replacing any component, automatically search beUI (MCP `https://mcp.beui.dev/mcp` or its static registry) and adopt the match instead of building from scratch. Order → beUI → beUI modified → from scratch with a recorded reason. This package runs the beUI stack since 2026-09-17: preserve useful beUI anatomy, logic, motion and geometry; change dimensions only for a documented need and validate the affected states; `cn` lives in `src/lib/utils.ts` (internal, never exported); tokens use shadcn names with BEDS values; `motion/react` with BEDS easing and `useReducedMotion` is the interaction-motion engine — never add CSS `@keyframes`/`transition` outside the shrinking allowlist in `check-library.mjs`. No `npx shadcn add`, no runtime import of beUI. Record slug/URL/date and attribute upstream. [External component sourcing](docs/EXTERNAL-COMPONENT-SOURCING.md) owns the contract.
- For every BEDS UI task, automatically load and apply `better-interface` plus `better-accessibility`, `better-layout`, `better-writing`, `better-typography`, `better-colors`, `better-ui` before design/code decisions; never wait for an explicit skill request. Read full entrypoints and relevant references. Follow [Interface quality](docs/INTERFACE-QUALITY.md), then repeat the affected-surface review before handoff. Missing skills/evidence forbid approval; docs-only work is not a fabricated UI audit.
- Consumers must route this protocol from their own applicable `AGENTS.md`; an installed package's nested instructions are not automatically discovered for application files. Resolve installed skill paths on the current machine; never commit personal paths.
- For SaaS landing-page creation or review of positioning, hero, benefits, proof, offer presentation or CTAs, automatically read and apply the complete [marc-lou-landing-page skill](skills/marc-lou-landing-page/SKILL.md) and its relevant references. [Landing-page routing](docs/LANDING-PAGE-SKILL.md) owns consumer setup and scope. Keep Better and approved DS contracts; do not apply this lens automatically to dashboards, post-signup onboarding or cosmetic-only primitive maintenance. No implied offer changes or conversion guarantee.
- Preserve M/D/A/U evidence labels and licenses. Do not promote an old measurement over a later explicit adoption.
- Library check: `npm run check`. Consumer check: `node scripts/check-consumer.mjs <explicit-ui-roots>`. Docs: `npm run check:docs`. Tooling regressions: `npm run test:guards`. Rebuild before `npm run check:artifact`.
- Follow [Governance](docs/GOVERNANCE.md) for change-specific gates and delivery statuses. Missing required evidence is pending, not passed. Technical evidence is not aesthetic approval.
- Do not change production, the old prototype or installed consumers implicitly. Commit, push, publication, integration and deployment need separate authorization; this protocol does not grant it.
