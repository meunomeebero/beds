# BEDS portable UI — package rules

Read [the documentation map](docs/README.md), then only the affected contract. In this repository, edit canonical `docs/design/espaco-library/`; package `docs/` is generated by the build.

- This portable DS is separate from legacy Curriculol typography/palette and the old Espaço prototype. [Foundations](docs/FOUNDATIONS.md) owns approved visuals; do not mix systems.
- Two fixed themes; one validated provider brand color. Named semantic variants only. No consumer CSS, token overrides, arbitrary visual props or raw visual replacements.
- Components own presentation and semantics; callers own copy, data, requests, routing and business rules. Use controlled state; never invent successful operations.
- A missing pattern requires a shared contract/API, catalog example, states and focused light/dark responsive evidence. No local styling workaround.
- For every BEDS UI task, automatically load and apply `better-interface` plus `better-accessibility`, `better-layout`, `better-writing`, `better-typography`, `better-colors`, `better-ui` before design/code decisions; never wait for an explicit skill request. Read full entrypoints and relevant references. Follow [Interface quality](docs/INTERFACE-QUALITY.md), then repeat the affected-surface review before handoff. Missing skills/evidence forbid approval; docs-only work is not a fabricated UI audit.
- Consumers must route this protocol from their own applicable `AGENTS.md`; an installed package's nested instructions are not automatically discovered for application files. Resolve installed skill paths on the current machine; never commit personal paths.
- Preserve M/D/A/U evidence labels and licenses. Do not promote an old measurement over a later explicit adoption.
- Library check: `npm run check`. Consumer check: `node scripts/check-consumer.mjs <explicit-ui-roots>`. Docs: `npm run check:docs`. Tooling regressions: `npm run test:guards`. Rebuild before `npm run check:artifact`.
- Follow [Governance](docs/GOVERNANCE.md) for change-specific gates and delivery statuses. Missing required evidence is pending, not passed. Technical evidence is not aesthetic approval.
- Do not change production, the old prototype or installed consumers implicitly. Commit, push, publication, integration and deployment need separate authorization; this protocol does not grant it.
